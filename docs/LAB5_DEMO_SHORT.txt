1. Что реализовано

В проекте добавлена bulk-операция для бронирований, показана разница между выполнением bulk-операции с транзакцией и без нее, использованы Stream API и Optional в сервисном слое, а также написаны unit- и интеграционные тесты для ключевых сценариев лабораторной.

3. Bulk с транзакцией и без транзакции

Где показывать в коде:
- /Users/saku10/Desktop/Java/src/main/java/pitchmarketplace/service/BookingService.java:76
- /Users/saku10/Desktop/Java/src/main/java/pitchmarketplace/service/BookingService.java:85
- /Users/saku10/Desktop/Java/src/main/java/pitchmarketplace/controller/DemoController.java:82
- /Users/saku10/Desktop/Java/src/main/java/pitchmarketplace/controller/DemoController.java:108
- /Users/saku10/Desktop/Java/src/main/java/pitchmarketplace/dto/BulkBookingTransactionDemoResultDto.java:6

Что говорить:
- метод createBulk(...) помечен @Transactional, поэтому при ошибке откатывается вся bulk-операция
- метод createBulkWithoutTransaction(...) не помечен @Transactional, поэтому часть данных может сохраниться
- для защиты это удобно показывать через demo-endpoint

Endpoint без транзакции:
POST http://localhost:8080/api/v1/demos/transactions/bulk-bookings/without-transaction

Endpoint с транзакцией:
POST http://localhost:8080/api/v1/demos/transactions/bulk-bookings/with-transaction

Запрос для демонстрации разницы:
[
  {
    "pitchId": 1,
    "organizerId": 1,
    "startAt": "2026-05-10T18:00:00",
    "endAt": "2026-05-10T20:00:00",
    "status": "CREATED"
  },
  {
    "pitchId": 1,
    "organizerId": 999999,
    "startAt": "2026-05-11T18:00:00",
    "endAt": "2026-05-11T20:00:00",
    "status": "CONFIRMED"
  }
]

Как объяснять результат:
- без транзакции первый элемент сохранится, второй упадет с ошибкой, поэтому after.bookings будет больше before.bookings на 1
- с транзакцией при ошибке откатится вся операция, поэтому after.bookings будет равно before.bookings


4. Где используется Stream API

Где показывать в коде:
- /Users/saku10/Desktop/Java/src/main/java/pitchmarketplace/service/BookingService.java:40
- /Users/saku10/Desktop/Java/src/main/java/pitchmarketplace/service/BookingService.java:78

Что говорить:
- Stream API используется для обработки коллекций в декларативном стиле
- в findAll() поток превращает список Booking в список BookingDto
- в createBulk() поток превращает список BookingUpsertRequest в список созданных BookingDto

Для чего нужен map в Stream API:
- map преобразует каждый элемент потока в новый элемент
- у меня это, например, преобразование Booking в BookingDto или BookingUpsertRequest в результат сохранения


5. Где используется Optional

Где показывать в коде:
- /Users/saku10/Desktop/Java/src/main/java/pitchmarketplace/service/BookingService.java:99
- /Users/saku10/Desktop/Java/src/main/java/pitchmarketplace/service/BookingService.java:113
- /Users/saku10/Desktop/Java/src/main/java/pitchmarketplace/service/BookingService.java:124

Что говорить:
- Optional нужен для безопасной работы с возможным отсутствием значения вместо прямой работы с null
- в normalizeBulkRequests(...) Optional используется для проверки, что список не null и не пустой
- в findById(...).orElseThrow(...) Optional помогает явно обработать ситуацию, когда сущность не найдена

Для чего нужен Optional:
- делает отсутствие значения явным
- уменьшает риск NullPointerException
- заставляет программиста явно решить, что делать, если объекта нет
